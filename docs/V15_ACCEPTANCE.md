# ODPAR: Territorial Domain v15 — Acceptance Record

Release line: **15.0.0 / API 15 / FFI ABI 2 / save schema 8**

This record describes the implementation shipped in this source bundle. Android APK compilation is intentionally an external gate because this container does not contain Flutter/Dart or an Android SDK. No APK is claimed by this bundle.

## Product architecture

- [x] Flutter/Dart is the Android host/UI.
- [x] FFI is a versioned fail-closed boundary.
- [x] C11 remains authoritative for simulation, inventory, crafting, resources, artifacts, bots, territory, chunks and save state.
- [x] C renderer produces the 3D world, avatar textures, item cards, glyphs, terrain, trails, territory contours, remote/artifact views and music-reactive world effects.
- [x] Simulation remains fixed at 120 Hz.
- [x] No WebView and no gameplay copy in Dart/Kotlin.

## Territorial gameplay

- [x] Player and bots are clean cube actors.
- [x] Head and committed trail are distinct.
- [x] Self-trail is not lethal; enemy committed trail resolves before and after movement.
- [x] Continuous fixed-point TrailPath feeds the ribbon renderer.
- [x] Manual drop uses the selected slot and 90-tick anti-repickup.
- [x] Open Domain has no terminal 55% victory.
- [x] Death preserves nation territory/deployed infrastructure and uses safe respawn.
- [x] Ranking share is based on claimed territory rather than a finite-world percentage.

## Items, economy and artifacts

- [x] Generic ItemDefinition / ItemStack model; no new carried_* architecture.
- [x] 4-slot base inventory + backpack equipment expanding to 12 slots.
- [x] Resources: wood, stone, iron.
- [x] Axes/pickaxes: wood, stone and iron tiers with durability/work-based wear.
- [x] Harvesting rules, deterministic yields and physical world drops.
- [x] Transactional crafting with station validation, resource validation and output-space validation.
- [x] Workbench and Smithy have separate recipe domains.
- [x] Chest storage is persistent and transactional; non-empty chest cannot be picked up.
- [x] Generic artifacts/capabilities cover workbench, smithy, chest and turret.
- [x] Turrets have wood/stone/iron tiers, readable ammo, reprogram chips and tier upgrades.
- [x] Neutral procedural turret ownership follows territorial conquest.
- [x] DEFENSE / HARVEST turret modes; harvesting creates physical wood and consumes ammo.
- [x] Remote turret view is generated by the C renderer.

## Open world and persistence

- [x] Global 64-bit fixed-point actor/entity positions with floating render/simulation origins.
- [x] Deterministic 32x32 chunks independent of visit order.
- [x] Continuous global heightfield and seam-safe chunk boundaries.
- [x] Plain / forest / rocky biomes with deterministic resource distribution and bootstrap progression.
- [x] Dynamic chunk/entity stores remove old fixed world-size ceilings.
- [x] ACTIVE / DIRTY / SLEEPING summaries and spatial indexing separate existence from render cost.
- [x] Distant bots retain authoritative economic progression without requiring rendering.
- [x] World map queries use global viewport/resolution rather than loading the whole world into Dart.
- [x] Save/load is versioned, checksummed and round-trip deterministic.
- [x] Flutter/Android host uses atomic temp -> fsync -> rename persistence and autosave hooks.

## Renderer and presentation

- [x] Continuous heightfield terrain; chunk grid is not an aesthetic boundary.
- [x] Directional/ambient terrain response, sky, haze, depth fog and terrain-following shadows.
- [x] Territory uses material tint + marching-squares global contours rather than tile outlines.
- [x] Trails use continuous terrain-following ribbons without /\|\/ cell stitching.
- [x] Low-poly trees/rocks/resources, deterministic microscenery and distance culling.
- [x] Immersive scale hierarchy: compact cube actors, multi-metre resource trees and substantial stone/iron deposits with collision footprints matched to visible mass.
- [x] Wood/stone/iron turrets have distinct structural silhouettes instead of material colour alone.
- [x] Reprogram/ascension chips are double-sided physical hardware cards with material frames, functional circuitry and visible contact fingers.
- [x] Shared TextureStore with mip levels; six RGBA avatar faces use real UV sampling.
- [x] Shared GlyphAtlas replaces turret seven-segment text and supports renderer labels.
- [x] Vertical floating tech item cards.
- [x] First-person and multiple third-person distances.
- [x] Camera preview and remote view are presentation-only and do not alter gameplay hash.

- [x] Inventory does not pause the simulation.

- [x] Camera sensitivity/distance editor with C-rendered preview.

- [x] Crafting, repair and chest flows are connected to native transactions.

## Music and credits

- [x] MediaExtractor + MediaCodec + AudioTrack path supplies decoded PCM directly to C through JNI.
- [x] C analyzer exposes energy/bass/low-mid/mid/high/onset/beat/activity with normalization/reset behavior.
- [x] Music is presentation-only; deterministic tests protect gameplay hash from music input.

## External gate for the APK builder

Run from `app/flutter/` on a machine with Flutter + Android SDK:

```sh
flutter pub get
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build apk --release
```

The source bundle deliberately does **not** claim these commands were executed in this container.
